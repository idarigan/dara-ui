# Getting Started

## Install

```bash
npm install dara-ui
# or
pnpm add dara-ui
yarn add dara-ui
```

Peer dependencies: `react` and `react-dom` (18+).

## Import styles

**Project without Tailwind** — import the prebuilt stylesheet:

```tsx
// main.tsx or App root
import "dara-ui/style.css";
```

**Project that uses Tailwind v4** — don't import `style.css`. Import the
Tailwind entry from your own main CSS file instead:

```css
/* src/index.css */
@import "tailwindcss";
@import "dara-ui/tailwind.css";
```

`style.css` carries its own compiled copy of Tailwind utilities
(`grid-cols-1`, `sm:grid-cols-2`, `hidden`, `md:block`…). Loaded next to your
Tailwind build, the same classes exist twice and whichever file loads last
overrides your responsive variants, so only some breakpoints apply.
`dara-ui/tailwind.css` ships only Dara's tokens, fonts, glass and glow styles
and tells your Tailwind to scan Dara's components, so every utility is generated
once, in the right order.

## Minimal setup

```tsx
import { ThemeProvider, Button, ToastProvider } from "dara-ui";
import "dara-ui/style.css";

export default function App() {
  return (
    <ThemeProvider defaultTheme="nightfall">
      <ToastProvider>
        <Button variant="primary">Hello Dara</Button>
      </ToastProvider>
    </ThemeProvider>
  );
}
```

## With i18n + direction

```tsx
import {
  ThemeProvider,
  ToastProvider,
  I18nProvider,
  translations,
} from "dara-ui";

export default function App() {
  return (
    <ToastProvider>
      <I18nProvider translations={translations} defaultLanguage="en">
        <ThemeProvider defaultTheme="nightfall">{/* app */}</ThemeProvider>
      </I18nProvider>
    </ToastProvider>
  );
}
```

`I18nProvider` sets `lang` and `dir` on `<html>`. Components listen to `dir` for RTL.

## Tailwind / CSS variables

Dara UI ships design tokens as CSS custom properties (see `tokens.css`). Themes switch with:

```html
<html data-theme="nightfall"></html>
```

or via `ThemeProvider` / `ThemeChanger`.

## TypeScript

All public components export typed props. Example:

```tsx
import type { ButtonProps, BadgeProps } from "dara-ui";
```

## Do / Don't

## Glow layer

Glows on elements in the normal page are painted in a shared layer so they can
spill over `overflow: hidden` parents. They always stay **under** fixed and
sticky UI (navbar, toasts, modals, back-to-top). Glows on elements inside a
scroll container, or inside a fixed/sticky parent, use the element's own
`box-shadow`, so they scroll with it and are never left behind.

- Custom fixed element that isn't detected? Add `data-glow-occluder`.
- Decorative fixed overlay that shouldn't hide glows? Add `data-glow-occluder="false"`.
- Glow tokens you can use in your own components:
  `shadow-[var(--shadow-glow-primary)]`, `hover:shadow-[var(--shadow-glow-accent)]`,
  `hover:shadow-[var(--shadow-glow-primary-strong)]`, …
